# 작업 끝나면 커밋 · 푸시

## 언제 쓰나

- 파일을 고치는 작업을 마치고, 시험 도구 등으로 확인까지 끝냈을 때 (사용자가 따로 말하지 않아도 바로 쓴다)
- "커밋해 줘", "푸시해 줘", "올려 줘" 라고 할 때

## 언제 쓰지 않나

- 확인에서 오류가 났거나 확인을 아직 못 했을 때 : 커밋하지 않고, 무엇이 안 되는지 먼저 알린다
- 파일을 읽기만 하고 고친 것이 없을 때
- 사용자가 "커밋하지 마" 라고 했을 때

## 어떤 순서로 하나

1. `git status --short` 로 바뀐 파일을 본다
2. 이번 작업에서 고친 파일만 이름을 하나씩 적어 `git add` 한다 (`git add .` 이나 `git add -A` 는 쓰지 않는다)
3. 이번 작업과 상관없는 바뀐 파일이 있으면 넣지 않고, 답에 "넣지 않은 파일" 로 알린다
4. `.env` 처럼 비밀 값(서비스 사용 권한 키)이 든 파일이 올라가 있지 않은지 `git diff --cached --name-only` 로 확인한다. 있으면 멈추고 알린다
5. 서로 다른 작업이 섞여 있으면 작업마다 커밋을 나눈다
6. 커밋한다
   - 첫 줄은 지난 커밋들처럼 영어로, 무엇을 왜 바꿨는지 한 줄로 적는다
   - 필요하면 빈 줄 뒤에 "- " 로 시작하는 줄로 자세히 적는다
   - 맨 끝에 빈 줄을 두고 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` 을 적는다
7. `git fetch origin` 뒤 `git status -sb` 로 GitHub 와 비교한다
   - 내 쪽이 앞서기만 하면 `git push origin main` 한다
   - GitHub 쪽에 내가 없는 기록이 있으면 푸시하지 않고 멈춰서 알린다
8. 푸시 뒤 `git status -sb` 로 GitHub 와 기록이 같아졌는지 확인한다

## 무엇을 내놓나

- 커밋 번호 앞 7자리와 첫 줄
- 들어간 파일
- 넣지 않은 파일 (있을 때만)
- 푸시한 곳 (GitHub 주소와 갈래 이름)
- 내 컴퓨터와 GitHub 의 기록이 같아졌는지

## 지킬 것

- `git push --force`, `git reset --hard`, `--no-verify` 는 쓰지 않는다
- `.env` 는 절대 커밋하지 않는다
- 푸시가 실패하면 다시 밀어붙이지 말고, 나온 오류를 그대로 보여 주고 멈춘다
